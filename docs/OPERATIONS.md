# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在“分组交接结论”中按组核对：`READY` 表示已对账可签发，`HELD` 表示该组须暂缓，`PENDING_REVIEW` 表示来源更新后需复核。
3. 同一记录号在不同业务组内容冲突时，不要签发任一涉事组；系统会把所有涉事组标为暂缓，其余已对账组可分别签发。坏行无法识别业务组时，所有未签发组一律暂缓。
4. 修复来源文件后，可重新上传为新批次，或通过 `POST /api/runs/<id>/source` 更新。记录跨组时原组和新组都重算；受影响的已签发组转待复核，原运行证据和分组签发件仍可按原链接查回。
5. 对仍有差异的版本填写暂缓意见；签发时保存分组签发件，并导出复核证据用于交接。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。
